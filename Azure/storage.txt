Azure Storage Account is a cloud-based storage solution provided by Microsoft Azure. It offers various types of storage services, including Blob Storage, File Share, Queue Storage, and Table Storage.

ADLS (Azure Data Lake Storage) is a scalable and secure data lake solution built on top of Azure Storage Account. It provides a hierarchical namespace and is optimized for big data analytics workloads. 
ADLS Gen2 is the latest version of Azure Data Lake Storage, which combines the capabilities of both Blob Storage and File Share, allowing you to store and analyze large volumes of data efficiently.

ADLS has better performance and scalability compared to traditional Blob Storage, making it suitable for big data analytics scenarios.
 It also supports features like hierarchical namespaces, which allow for better organization and management of data.

# You have to enable ADLS Gen2 on your storage account to take advantage of its features. Heirarchical namespaces allow you to organize your data in a directory-like structure, making it easier to manage and access your data.

!!! Accessing Azure Storage Account
To access Azure Storage Account, you can use various tools and SDKs provided by Microsoft. Some common methods include:
1. Azure Portal: You can access and manage your storage account through the Azure Portal, which provides a user-friendly interface for managing your storage resources.
2. Azure Storage Explorer: This is a free tool that allows you to easily manage and access

ACCESS TOKEN / Shared Access Signature (SAS) / Storage Account Keys: These are different authentication methods that you can use to access your storage account programmatically.
- Access Token: This is a token that is generated by Azure Active Directory (AAD) and can be used to authenticate and access Azure Storage Account resources.
- Shared Access Signature (SAS): This is a URI that grants restricted access to Azure Storage Account resources. It allows you to specify permissions, expiration time, and other parameters to control access to your storage resources.
- Storage Account Keys: These are the primary and secondary keys that are associated with your storage account. They can be used to authenticate and access your storage account resources, but it is recommended to use them with caution as they provide full access to your storage account.


>> Access keys are not recommended for production use as they provide full access to your storage account. 
It is better to use Access Tokens or Shared Access Signatures (SAS) for secure and controlled access to your storage resources.

### ACCESS TIERS
Azure Storage Account offers different access tiers to optimize costs based on the frequency of data access. The access tiers include:
1. Hot Tier: This tier is designed for frequently accessed data. It provides low latency and
high throughput, making it suitable for active data that is accessed frequently.
2. Cool Tier: This tier is designed for infrequently accessed data. It offers lower storage costs compared to the hot tier but has higher access costs. It is suitable for data that is accessed less frequently but still needs to be readily available.
3. Archive Tier: This tier is designed for rarely accessed data that can tolerate higher latency. It offers the lowest storage costs but has higher access costs and retrieval times. It is suitable for long-term storage of data that is not expected to be accessed frequently.
You can choose the appropriate access tier for your data based on its access patterns and cost requirements.    



## FILE Share
it is used to share a central storage over the SMB protocol
> it connects with resources like virtual machines, on-premises servers, and other Azure services. It allows you to create file shares that can be accessed by multiple users and applications simultaneously.
File shares are commonly used for scenarios such as:
- Storing and sharing files across multiple virtual machines or applications.
- Providing a central location for storing application data that needs to be accessed by multiple instances of an application.
- Enabling lift-and-shift migrations of applications that rely on file shares for storage.
File shares can be accessed using various tools and protocols, including SMB, REST API, and Azure
SMB stands for Server Message Block, which is a network file sharing protocol that allows applications to read and write to files and request services from server programs in a computer network. It is commonly used for accessing file shares in Azure Storage Account.


## QUEUE Storage
Queue Storage is a service that allows you to store and manage messages in a queue. It is designed for scenarios where you need to decouple components of an application and enable asynchronous communication between them.
Queue Storage is commonly used for scenarios such as:
- Building scalable and distributed applications that require asynchronous processing.
- Implementing message-based communication between different components of an application.
- Enabling reliable and durable messaging for scenarios such as order processing, task scheduling, and event
handling.
Queue Storage can be accessed using various tools and SDKs provided by Microsoft, including Azure Portal,
Azure Storage Explorer, and Azure SDKs for different programming languages. You can use these tools to create queues, add messages to queues, retrieve messages from queues, and manage your queue storage resources effectively.
it uses PUB/SUB model for communication, where producers publish messages to a queue and consumers subscribe to the queue to receive messages. This allows for decoupling of components and enables asynchronous communication between them.

Azure Table Storage is commonly used for scenarios such as:
- Storing and querying large volumes of structured data, such as user profiles, device information,
and application logs.
- Building scalable and distributed applications that require fast access to structured data.
- Enabling flexible schema design, allowing you to store different types of data in the same table without the need for a predefined schema.
Azure Table Storage can be accessed using various tools and SDKs
